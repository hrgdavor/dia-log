# CodeBuddy — `@CB.StrPacker`

Marker-driven source generation for fixed UTF-8 field prefixes. `@CB.StrPacker`
replaces a runtime-initialized static field block with **gen-time computed
compile-time constants**: the packed little-endian long words and the byte
length become Java literals, so class init no longer runs `packWord(...)` and
`KEY_X.length` for every key.

The tool lives in the `project-automation` module (`CodeBuddy` dispatcher +
`StrPacker` instruction processor).

## How it works

You write a **marker comment** directly above a field block. The marker is the
source of truth; the lines below it are regenerated by the tool and must not be
hand-edited:

```java
    // @CB.StrPacker <modifiers> <NAME> = `<literal>`
```

- `<modifiers>` — the declaration modifiers, e.g. `private static final`.
- `<NAME>` — the base field name; the generator derives `NAME_W0..NAME_W3`,
  `NAME_LEN` and `NAME_LEN_BUF`.
- `<literal>` — the raw UTF-8 string, **backtick-delimited** so JSON text with
  quotes and backslashes can be written without escaping (backticks are not
  allowed inside the literal).

Running CodeBuddy replaces the block below the marker with:

```java
    // @CB.StrPacker private static final KEY_TS = `{"ts":`
    private static final byte[] KEY_TS = "{\"ts\":".getBytes(StandardCharsets.UTF_8);
    private static final long KEY_TS_W0 = 0x00003a227374227bL;
    private static final int KEY_TS_LEN = 6;
    private static final int KEY_TS_LEN_BUF = 8;
```

| Generated member | Meaning |
| --- | --- |
| `byte[] NAME` | the literal's UTF-8 bytes (re-emitted from the marker, so it can never drift) — stream fallback path |
| `long NAME_W0..NAME_W3` | one little-endian `packWord` per 8-byte window (offsets 0, 8, 16, 24), as 16-digit hex literals — direct-buffer path (one 8-byte store per word) |
| `int NAME_LEN` | the UTF-8 byte length, as a literal |
| `int NAME_LEN_BUF` | the buffer reserve the packed store occupies — `NAME_LEN` rounded up to whole 8-byte word slots (e.g. 9 → 16), used directly by the inline capacity checks |

Word `i` is emitted when the UTF-8 length exceeds `i*8`, so a 1-byte..8-byte
literal gets 1 word, 9..16 bytes get 2 words, 17..24 get 3 words, and 25..32
bytes get 4 words; `NAME_LEN_BUF` is `NAME_LEN` rounded up to a multiple of 8.
**Literals longer than 32 UTF-8 bytes cannot be fully packed, so they fall back
to a `byte[]` + `NAME_LEN` block with no packed words and no `NAME_LEN_BUF`** —
the stream fallback path writes the `byte[]` directly.

## Examples

### 1 word — short key (6 bytes)

```java
    // @CB.StrPacker private static final KEY_TS = `{"ts":`
    private static final byte[] KEY_TS = "{\"ts\":".getBytes(StandardCharsets.UTF_8);
    private static final long KEY_TS_W0 = 0x00003a227374227bL;
    private static final int KEY_TS_LEN = 6;
    private static final int KEY_TS_LEN_BUF = 8;
```

### 2 words — key longer than 8 bytes (9 bytes)

```java
    // @CB.StrPacker private static final KEY_LOGGER = `"logger":`
    private static final byte[] KEY_LOGGER = "\"logger\":".getBytes(StandardCharsets.UTF_8);
    private static final long KEY_LOGGER_W0 = 0x22726567676f6c22L;
    private static final long KEY_LOGGER_W1 = 0x000000000000003aL;
    private static final int KEY_LOGGER_LEN = 9;
    private static final int KEY_LOGGER_LEN_BUF = 16;
```

### 4 words — full window (25 bytes)

```java
    // @CB.StrPacker private static final KEY_LONG = `"someLongKeyName":"value"`
    private static final byte[] KEY_LONG = "\"someLongKeyName\":\"value\"".getBytes(StandardCharsets.UTF_8);
    private static final long KEY_LONG_W0 = 0x6e6f4c656d6f7322L;
    private static final long KEY_LONG_W1 = 0x656d614e79654b67L;
    private static final long KEY_LONG_W2 = 0x65756c6176223a22L;
    private static final long KEY_LONG_W3 = 0x0000000000000022L;
    private static final int KEY_LONG_LEN = 25;
    private static final int KEY_LONG_LEN_BUF = 32;
```

The write side stores one little-endian VarHandle long per 8-byte window via
the public `WriteOps.LE_LONG` handle: `WriteOps.LE_LONG.set(buf, pos, w)`
writes a full 8-byte word, and the cursor advances by the bytes the key
consumes. Field names are static constants, so each call site does its range
check inline and stores the prefix directly — `buf[pos++] = ','` then
`LE_LONG.set(...)` + `pos += n` per word — and values are written separately
(`writeStringDirect` / `WriteOps.writeEscapedJsonString`). There are no
combined prefix+value helpers and no length-dispatch helper. A key whose last
word delivers fewer than 8 bytes is stored as a full 8-byte word and the cursor
advances by the actual length (`LE_LONG.set(...)` + `pos += tailLen`, see
`doc/perf-exploration/t8-packed-word-varhandle-stores.md`); the inline capacity checks
reserve the generated `NAME_LEN_BUF` constant (the whole 8-byte word slots) so
that overwrite store always has a full slot reserved.

### Fallback — literal longer than 32 bytes (no packed words)

```java
    // @CB.StrPacker private static final KEY_LONG = `"veryLongKeyWithVeryLongName":"value"`
    private static final byte[] KEY_LONG = "\"veryLongKeyWithVeryLongName\":\"value\"".getBytes(StandardCharsets.UTF_8);
    private static final int KEY_LONG_LEN = 37;
```

37 UTF-8 bytes do not fit in 4 words, so only the byte[] and the length are
emitted; the key is written through the stream path.

## Running CodeBuddy

From the repository root (JDK 25, real Maven — see `AGENTS.md`):

```powershell
$env:JAVA_HOME = "C:\Program Files\Java\jdk-25"
& "D:\programs\mvn\bin\mvn.cmd" -pl project-automation compile exec:java "-Dexec.mainClass=hr.hrg.dialog.tools.CodeBuddy"
```

A repo root may be passed as the first program argument:
`CodeBuddy [repoRoot]`.

The tool scans all `*.java` sources for `@CB.*` markers, regenerates every
`@CB.StrPacker` block, validates that the rewritten source still parses
(JavaParser, JAVA_25 language level) and writes only files that changed.

## Invariants

- **Marker is the source of truth.** Any hand-edit below a marker is overwritten
  on the next run — change the literal in the marker instead.
- **Idempotent.** The generated block matches its own consumption pattern;
  running the tool twice yields the same source (the committed
  `JsonLogWriter.java` should always be up to date — a test enforces this).
- **Line endings preserved.** CRLF and LF files stay as they are.
- **packWord equivalence.** The generator's `packWord(byte[], off)` must stay
  byte-for-byte identical to `JsonLogWriter.packWord`; both the source-level
  test (`StrPackerTest.jsonLogWriterGeneratedBlocks_matchPackWord`) and the
  runtime reflection test (`JsonLogWriterStrPackerTest`) verify every emitted
  literal against it.
- **Cap.** `MAX_WORDS = 4` / `MAX_LITERAL_BYTES = 32`; longer literals fall back
  to a `byte[]` + `NAME_LEN` block instead of emitting partial packed words.

## Adding a new packed key

1. Pick the JSON prefix, e.g. `"traceId":`.
2. Write the marker above where the block should live:

   ```java
   // @CB.StrPacker private static final KEY_TRACE_ID = `"traceId":`
   private static final byte[] KEY_TRACE_ID = "\"traceId\":".getBytes(StandardCharsets.UTF_8);
   private static final long KEY_TRACE_ID_W0 = packWord(KEY_TRACE_ID, 0);
   private static final int KEY_TRACE_ID_LEN = KEY_TRACE_ID.length;
   private static final int KEY_TRACE_ID_LEN_BUF = 0; // regenerated by CodeBuddy
   ```

   (the placeholder block can be anything with the right shape — or omitted; the
   tool generates the block from the marker alone)
3. Run CodeBuddy — the placeholders are replaced with literal constants.
4. Use the constants in the writer: the inline prefix range check + store,
   then the value written separately, e.g.
   `if (pos + 1 + KEY_TRACE_ID_LEN_BUF > limit) { rbo.grow(...); ... }`
   followed by `buf[pos++] = ','; WriteOps.LE_LONG.set(buf, pos,
   KEY_TRACE_ID_W0); pos += 8; pos = writeStringDirect(rbo, pos, value);`.

## Tests

- `project-automation/.../StrPackerTest.java` — marker parsing, word-window
  generation (1..4 words), the >32-byte byte[] fallback, source
  rewriting/idempotency/CRLF, and verification that every committed block in
  `JsonLogWriter.java` matches `packWord`.
- `logback/.../JsonLogWriterStrPackerTest.java` — runtime reflection check that
  the compiled constants equal `JsonLogWriter.packWord(KEY_*, off)` / `KEY_*.length`.
