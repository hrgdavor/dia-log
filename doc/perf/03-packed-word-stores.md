# 03 — Packed word stores: static data as VarHandle words

Field names (`"level":`, `"ts":`, …) and JSON literals (`null`, `true`,
`false`) are **fixed bytes**. The cost of writing them the naive way is a
virtual `write(byte[])` plus an `arraycopy` per field. The fix: precompute the
bytes as **little-endian `long`/`int` words at build time** and store each word
with one VarHandle store.

## Packing the data

Each fixed prefix becomes:

- a `byte[]` (the UTF-8 bytes) for the stream fallback path, and
- one packed `long` per 8-byte window of those bytes (`W0`, `W1`, …), plus
- the byte length (`LEN`) and the whole-word-slot buffer reserve (`LEN_BUF`).

In this project these are generated by the `@CB.StrPacker` CodeBuddy marker
(see [`doc/codebuddy-strpacker.md`](../codebuddy-strpacker.md)); the generator
computes the literals at generation time, so the class has **compile-time
constants** — no `packWord` call at class init, no `KEY_X.length` at runtime.

```java
// @CB.StrPacker private static final KEY_LOGGER = `"logger":`
private static final byte[] KEY_LOGGER = "\"logger\":".getBytes(StandardCharsets.UTF_8);
private static final long KEY_LOGGER_W0 = 0x22726567676f6c22L; // bytes 0..7
private static final long KEY_LOGGER_W1 = 0x000000000000003aL; // byte 8
private static final int KEY_LOGGER_LEN = 9;
private static final int KEY_LOGGER_LEN_BUF = 16;              // 9 -> whole word slots
```

## Storing the words

`WriteOps.LE_LONG` is the `byte[]` VarHandle view (little-endian, alignment
free). Each window is **one store**:

```java
buf[pos++] = ',';                         // the prefix comma
WriteOps.LE_LONG.set(buf, pos, KEY_LOGGER_W0);  // full 8-byte window
pos += 8;
WriteOps.LE_LONG.set(buf, pos, KEY_LOGGER_W1);  // the 1-byte tail: full 8-byte store
pos += 1;                                       // advance by the real length
```

## The overwrite trick (full store, partial advance)

A 9-byte key takes two word *slots* (16 bytes) even though the second word
delivers one byte. Storing the tail as a **full 8-byte VarHandle store** and
advancing the cursor by only the real length is:

- one store regardless of tail length (measured flat at ~1.1 ns for tails 1..7,
  vs byte stores that grow linearly and `arraycopy` at ~5.3 ns), and
- safe because the capacity check reserved the whole slot (`LEN_BUF`) and the
  overwritten high bytes are re-written by the next store or excluded by the
  flush boundary (which respects `pos`, not `buf.length`).

This is why `LEN_BUF` exists: it is exactly the number of bytes the stores
touch, so the inline check matches the stores byte-for-byte.

## What it buys, measured

The packed-prefix store benchmark (`prefixesPackedDirect`) is ~4 ns for two
fields vs ~26 ns for the byte[]-prefix path — 6×. The T8 records in
[`doc/perf-exploration/`](../perf-exploration/) have the tail-store
comparison (`t8-packed-word-varhandle-stores.md`) and the packed-key
generation (`t6-packed-field-prefixes.md`).
